# 記録と解釈の二層モデル

[ADR-0](0000-north-star.md) で決めた「記録中心」を、データモデルの骨格として具体化する。用語は [GLOSSARY.md](../../GLOSSARY.md) に従う。

## 決定

### 境界：その謄本一通だけで確定できるか

データは**転写**と**解釈**の二層に分ける。その謄本一通だけを見て確定できるものは転写に、謄本をまたぐ判断は解釈に置く。

| 転写（謄本ごとに存在し、変更しない） | 解釈（謄本をまたぎ、育っていく） |
|---|---|
| 謄本、欄、記載 | 謄本と戸籍の対応、改製による戸籍のつながり |
| 記載人物（欄の主、本文中で言及された人） | 人物（記載人物の同定から成り立つ） |
| 事由（日付、種別、言及された名前を含む読み取り） | 出来事（複数の事由の同定から成り立つ） |
| 記載人物どうしの親子・養親子・夫婦・続柄 | 人物どうしの関係（同定を通して導く） |
| 戸主、前戸主、家督相続の事由 | 家（複数の戸籍にまたがる同一性） |
| 原文表記と、それに加える派生値 | 裁定（記載どうしの値の食い違いに対する判断） |

### 転写

- 謄本は 欄 → 記載 の階層で表す。欄には戸籍事項欄、戸主欄・筆頭者欄、各人の個人欄がある。
- 記載人物は、その謄本の中でだけ有効な存在とする。個人欄の主のほか、父母欄や身分事項の本文で名前だけ出てくる人も記載人物にし、どちらであるかの種別を持たせる。
- 謄本ごとに交付日と転写状況（未転写、一部転写、完全転写）を必須とする。
- 原文表記は Unicode の文字列とし、変体仮名や異体字セレクタ（IVS）で表せるものはそれで書く。表せない字形は代用字 `〓` を置き、どの字形の代わりかを謄本のページ番号とともに注記する（PDF 上の座標は任意）。他の謄本で別の字になっていても、転写の段階では揃えない。

### 解釈

- 同定・出来事・家・戸籍のつながり・裁定は、どれも根拠と確度（確定、推定、暫定）を伴う独立した判断として記録する。
- 記載人物どうしを `owl:sameAs` で結ぶことはしない。推論で両者の属性が混ざり、二層の区別が崩れるからである。
- 人物や出来事に値を直接書き込まない。値は同定された記載から問い合わせで導き出し、食い違いは検出して示す。裁定が記録されたときだけ、裁定の値を採る。

### 作成者と確認状況

ADR-0 の決定 7 に従い、転写と解釈のどちらにも作成者（収集者、他の人、AI エージェントとそのモデル）と確認状況（未確認、確認済み、確かめた人）を記録する。これは確度とは独立した軸である。AI エージェントが作った未確認の同定に、確度「確定」が付いていることもありうる。

### 物理的な配置

謄本一通を Turtle ファイル一つとし、解釈は別のファイルに置く。転写ファイルは一度書いたら変更しないので、変更しないことをファイル単位で確かめられる。

### 語彙

値の型（日付型、氏名型、住所型）には IMI コア語彙を使う。表記と標準化した値を両方持てるので、原文表記と派生値の関係にそのまま対応するからである。謄本、欄、記載、記載人物、同定、出来事、裁定、家などは独自の語彙として定義する。

### 検証

SHACL は二層で役割を分ける。

- **転写の形式**（必須項目、型、交付日、転写状況など）：違反（Violation）として弾く。
- **内容の整合性**（親子の年齢の逆転、同定された記載どうしの値の食い違いなど）：警告（Warning）にとどめる。戸籍そのものの誤記を忠実に転写したものはデータの誤りではないので、転写は拒否せず、裁定の候補として示す。

## Considered Options

- **記載人物を `owl:sameAs` で結ぶ**: 同定の根拠と確度を付ける場所がなく、推論器が属性を混ぜてしまう。却下。
- **人物に事実を直接書き込む（結論を保存する）**: 書き込んだ値が出典を持たない新しい事実のように振る舞い、記録への忠実さが崩れる。却下。
- **名前付きグラフ（TriG）で一ファイルにまとめる**: 変更しない転写と育っていく解釈を、ファイル単位では区別できなくなる。却下。
- **戸籍の同一性を転写側に置く**: 謄本には戸籍の識別子が書かれておらず、謄本と戸籍の対応は謄本をまたぐ判断になる。境界の規則に例外を作ることになるので却下。

## Consequences

- 今の `koseki.ttl` と SHACL は、このモデルで互換性を持たせずに置き換える。今の `身分事項イベント` は、転写側の事由と解釈側の出来事に分かれる。
- 往復を前提にした `ggs import`（3-way マージ）は削除する。既存の Gramps データの一度だけの移行は、暫定の同定を作る別の機能として作り直す。
- 具体的な作業は GitHub Issues で扱う。
