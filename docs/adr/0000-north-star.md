# 北極星：謄本に書かれたことを失わずに保存し、解釈と区別して積み上げる

用語は [GLOSSARY.md](../../GLOSSARY.md) に従う。

## 出発点

収集者は Gramps で戸籍に基づく系譜情報を管理していた。しかし Gramps の核家族モデルは戸籍の構造（家、戸主、改製、除籍、実親と養親の併記など）に合わず、和暦を西暦に換算して入力したことで原文表記も失われた。結果として、事実を確かめるには毎回元の謄本に戻る必要があった。GGS は、このデータ構造と管理モデルを一から設計し直すために作る。

## 決定

1. **北極星は記録への忠実さとする。** 謄本の記載を原文表記ごと一つも失わず、機械で検証できる形で長く保存する。可視化や他ツールとの相互運用はその上に乗る二次的な価値であり、そのために記録を丸めることはしない。
2. **主なユーザーは収集者とする。** 自分の家の謄本を手元に持ち、転写と同定を自ら行う個人の研究者を想定する。
3. **記録中心のモデルとする。** 一次データは謄本の転写であり、人物は記載人物の同定（根拠を伴う収集者の判断）から成り立つ。
   - 戸籍・謄本・記載を区別する。改製の前と後は別の戸籍として扱い、改製で結ぶ。
   - 転写は一度作ったら変更しない。戸籍に新しい記載が加われば、新たに交付された謄本を別の転写として加える。謄本の交付日は必須とする。
   - 部分的な転写を認める。その代わり、謄本ごとに転写状況を明示する。
   - 正規化した値（西暦、新字体など）は、原文表記に加える派生値として扱い、原文表記を置き換えない。原文表記には判読不能箇所、訂正・抹消の痕跡、記載された欄の位置も含める。
4. **対象範囲は日本の戸籍（明治民法から現行法まで）に限る。** 戸籍以外の資料（軍歴照会票など）は範囲外とする。
5. **Gramps と Graphviz は可視化のための一方向の出力先とする。** ファンチャートのような表示を得る手段であり、Gramps である必然性はない。既存の `.gramps` データは一度だけ移行し、暫定の同定として扱う。西暦に換算済みで原文表記がないため、事実の根拠にはしない。
6. **LLM は下書きを提案するだけとする。** 正本には SHACL による検証と収集者の確認を経たものだけを入れる。
7. **ローカルファーストとする。** データは収集者が管理するストレージ（Dropbox、Git など）に置き、GGS が自分から外部へ送信することはない。LLM などの外部サービスを使うかどうかは収集者が明示的に選ぶ。原本の画像（PDF）は GGS では保管せず、相対パスとハッシュ値で参照する。
8. **祖先経路番号は識別子にしない。** 祖先経路番号は収集者を起点とする便宜上のラベルで、起点となる人が変われば値も変わる（収集者の兄弟姉妹にとっては有効だが、子の世代にはずれる）。必要であれば同定の結果から算出して表示する。

## Considered Options

- **結論中心モデル（Gramps / GEDCOM 型）**: 人物と出来事を直接一つのグラフに書く方式。戸籍では同じ人物が転籍・分家・改製のたびに別の記録へ繰り返し現れるため、「何が書かれていたか」と「どう解釈したか」が混ざり、忠実さが崩れる。却下。
- **Gramps と対等に編集し、往復で情報を失わない方式**: 初期の叩き台で必須要件とされていた。Gramps 上の編集は解釈であって転写に戻すことができず、往復で情報を失わない仕組みの維持費も高い。却下。
- **汎用の系譜ツール**: 戸籍に固有の構造（家、改製、除籍）が薄まり、北極星と両立しない。却下。

## Consequences

- 今の実装（`koseki.ttl` の人物を中心にしたオントロジー、往復とマージを前提にした `ggs import`）は結論中心の設計であり、記録中心へ移す必要がある。移行の詳細は別の ADR と Issue で扱う。
- 初期の叩き台は [docs/archive/initial-handoff.md](../archive/initial-handoff.md) に移した。方針の拠り所は本 ADR に一本化し、叩き台と食い違う場合は本 ADR が優先する。
